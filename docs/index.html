    How it works

    PollA producer reads the MTA's eight GTFS-realtime feeds every 30 s and publishes each train's update to Kafka.
    Infer arrivalsSpark keeps every train's remaining stops in state; when a stop drops off its list, the train has arrived there.
    HeadwaysA second stateful query keeps the last arrival per line and platform and compares each new interval with the timetable.
    AlertsState timeouts raise a gap alert when a platform stays quiet too long, before the next train shows up.
    Publish15-minute event-time windows give reliability per line; the board is republished every few minutes.

    Duplicates are dropped within a watermark, every query checkpoints its state, and the stages are joined by Kafka topics so each can be replayed. Streaming runs as hourly sessions of about 50 minutes on GitHub Actions; the same code runs continuously with Docker Compose. Source code

    Data: MTA GTFS-realtime subway feeds and static timetable, used under the MTA's data feed terms. Not affiliated with or endorsed by the MTA. Check the MTA's own service alerts before you travel.
    Arrival times are inferred from train predictions, so individual headways can be off by up to a minute.
